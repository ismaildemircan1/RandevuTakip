## 2024-04-05 - Missing debouncing on search causing excessive API calls
**Learning:** The patient search input triggers a full Firestore collection fetch (`db.collection('patients').get()`) on *every* keystroke. For a large collection, this architecture will lead to major performance bottlenecks, massive unnecessary network overhead, and potential quota exhaustion. The backend data is repeatedly fetched and filtered client-side, multiplying the problem.
**Action:** Always wrap frequent user interactions (like search inputs) that trigger API calls or expensive database operations with a `debounce` function. In this specific application, adding debouncing significantly mitigates the flawed client-side filtering approach until a proper server-side or indexed query approach can be implemented.
