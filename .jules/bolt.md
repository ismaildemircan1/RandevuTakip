## 2024-05-17 - Debouncing search input to prevent full database scans
**Learning:** Found a critical performance bottleneck and anti-pattern in the Firestore implementation. The `patientSearch` input event listener was triggering `await db.collection('patients').get();` on *every single keystroke*. This causes an O(N) database read spike (fetching the *entire* collection each time) relative to the length of the search string typed, which is disastrous for performance, latency, and Firestore billing costs.
**Action:** Always implement debouncing on search inputs that trigger database queries or expensive operations. Even better, combine debouncing with optimized querying (like server-side filtering) if possible, rather than fetching the whole collection and filtering client-side.
