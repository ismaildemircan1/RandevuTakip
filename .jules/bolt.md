## 2026-04-09 - Firestore Input Debouncing\n**Learning:** The patient search feature was querying the entire 'patients' collection on every single keystroke. In a Firebase/Firestore architecture, this is an anti-pattern that leads to extremely high read costs and UI stuttering as the collection grows.\n**Action:** Always wrap search inputs that trigger network requests (especially Firestore reads) with a debounce function (e.g., 300ms) to ensure queries only fire after the user has paused typing.
